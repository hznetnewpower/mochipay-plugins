# Local validation and remaining acceptance

New Node.js, Python, C# and Java backends were compiled/syntax-checked and exercised against a local signed MochiPay fixture. Tests cover exact UTF-8/query signatures, server-owned pricing, stable request_id retries after a lost response, known-ID queries, immutable order binding, exact received amounts, unpaid/review states, forged and duplicate notifications, safe DTOs, HPP URL validation, private storage and restart recovery. No real MochiPay account, API credential, payment or wallet transfer was used.

C# was compiled/run with local Mono against .NET4.6.1 references; Windows VS2019/HttpListener URL ACL, HTTPS proxy and deployment still need acceptance. Java used JDK17 with its bundled JSON codec. PHP1.2.0 was syntax-parsed and source-reviewed; no local PHP runtime was available. Swift/Kotlin project structure and backend contract were checked; no Xcode/Android SDK simulator/device compilation was available. Do not call these results live payment or app-store certification.

For your staging acceptance: test one configured method with a small actual payment; close checkout before confirmation; confirm the server callback still verifies; reopen the same order; retry duplicate callbacks; test slow confirmation, underpayment/overpayment/expiry and wrong ownership. Retain the private attempt store and unchanged request_id after a timeout. Adapt staged paid_verified to your existing database's atomic payment/fulfillment update before production. Check the package README for exact runtime/configuration steps.
